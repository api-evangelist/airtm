# Airtm

> Airtm Inc. (Delaware, USA; FinCEN MSB #31000329787639) runs a digital dollar wallet and
> cross-border payments network for freelancers, contractors and businesses in emerging markets.
> User balances are USDC on Stellar, moved through 500+ local payment methods, a US virtual account
> and a USD virtual card. For businesses, Airtm publishes the Enterprise Payments API for
> programmatic payouts into 190+ countries, hosted-checkout payins, bulk payouts, withdrawals and
> reporting — plus an OAuth 2.0 / OIDC authorization server and a Wallet Resource (Connect) API for
> acting on an individual user's wallet on their behalf.

Generated by the API Evangelist enrichment pipeline, 2026-08-06. Airtm publishes no llms.txt of its
own (https://www.airtm.com/llms.txt 301s to a Cloudflare-challenged root; docs host returns 404).

## APIs

- [Airtm Enterprise API V2](https://docs.airtm.com/): Current REST API. 51 operations, 121 schemas, 8 declared webhooks. Base URL https://api.enterprise.airtm.com/v2. HTTP Basic auth (API key + secret).
- [Airtm Enterprise API V1](https://docs.airtm.com/): Legacy REST API, 18 operations. Base URL https://payments.air-pay.io. Superseded by V2; no announced sunset.
- [Airtm Wallet Resource (Connect) API](https://docs.airtm.com/): OAuth 2.0 resource server at https://api.enterprise.airtm.com/api/connect/v1. Scoped wallet:read / wallet:receive / wallet:send / kyc:status. Documented in prose only — no machine-readable spec.

## Key facts for agents

- Auth: HTTP Basic (`api_key:secret_key`) on the Enterprise API; OAuth 2.0 bearer on the Connect API. PKCE S256 is mandatory for authorization-code flows.
- Rate limit: 10 requests/second per API key, all endpoints, both environments. 429 on exceed. No rate-limit headers.
- Idempotency: `Idempotency-Key` header is REQUIRED on `POST /quotes`, `POST /transactions` and `CreateTransaction`. Same key + same body returns 200 with the original resource; different body returns 409.
- Pagination: cursor-based via `before`, `after`, `perPage`.
- Errors: proprietary `{code, message, data}` JSON envelope with an Airtm reason code — NOT RFC 9457. ~69 documented reason codes.
- Payouts are two-step: `CreatePayout` then `CommitPayout`. Creation alone pays no one.
- Every `wallet:send` on the Connect API parks at `pending_user_confirmation` until the user confirms a one-time code.
- Webhooks are delivered by Svix with signature verification; Airtm publishes its egress IPs for allowlisting.
- Sandbox at https://api.stg.enterprise.airtm.com — but there are NO magic test values (no test cards, no test tokens). Sandbox accounts need a real sandbox balance and you need at least two of them.
- No hosted MCP server, no A2A agent card, no AsyncAPI document, no public GitHub organization.
